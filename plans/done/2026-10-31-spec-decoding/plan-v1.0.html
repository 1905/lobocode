Faster qwen38-q6 output with speculative decoding: implementation plan v1.0

Date
2026-10-31
Status
done 2026-10-31 · image 0.2.5 published
Spec
./spec.html (with approval, fullsend)
Task
Measure qwen38-q6 output tok/s on a rented RTX 5090. Activate the fastest lossless speculation mode from llama.cpp in the pod agent. Measure again through the lobo up cloud operation. Then publish the image.
System
A Python bench (tools/spec_bench.py) controls llama-server on a bench pod and on lobo up pods. The Rust agent reads a new Spec mode from LOBO_SPEC. This mode adds --spec-type … flags to the end of the llama-server argv. Tests use the new image digest through lobo up --image before the change to latest-qwen38-q6.
Software
Rust (lobo-agent, tokio), llama.cpp b11118 llama-server, Python 3 stdlib (bench, unittest), RunPod REST v1, Docker on feesh9, GHCR
Cost limit
Total RunPod cost ≤ $10 (user, 2026-10-31). Cost in the plan: ~$3–4.

For agents: use superpowers:subagent-driven-development to do one task at a time. Subagents that change Rust code use Opus 5.5. No subagent can rent, publish or deploy an item. Only the orchestrator can do these operations.

#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum Spec { Off, Mtp, Ngram, #[default] MtpNgram }   // default variant = S5 winner
impl Spec {
    pub const VALID: &'static str = "off, mtp, ngram, mtp-ngram";
    pub fn parse(s: &str) -> Result<Spec, String>;         // "" => Spec::default(); unknown => Err naming VALID
    pub fn as_str(self) -> &'static str;                    // "off" | "mtp" | "ngram" | "mtp-ngram"
    pub fn args(self) -> Vec<String>;                       // flags appended after "--no-webui"
}
pub const MTP_DRAFT_MAX: u32;          // from S2, e.g. 2
pub const NGRAM_MATCH: u32;            // from S2 (llama.cpp default 24)
pub const NGRAM_MIN: u32;              // from S2 (default 48)
pub const NGRAM_MAX: u32;              // from S2 (default 64)
pub struct LlamaArgs { /* existing fields */ pub spec: Spec }

Cost control

Cost limit: $10. Cost in the plan: S2 ~1.5 h + S3 ~0.7 h + S7 ~0.7 h at $0.69–0.99/h ≈ $2–3.5. For each rental, record costPerHr and the start and stop times. Before each new rental, compare the total cost plus the cost in the plan for that rental with $8. If the sum is above this limit, do not get more rental pods. Write a report.
Risks
  • It is possible that llama.cpp rejects speculative decoding on this hybrid recurrent model. Batch A shows this in minutes. The T5.1 "no winner" path applies to this result.
  • A slow download of weights on a community host. Use the T2.1 stop rule and aria2c to control this risk.
  • The host for the T3/T7 data is different from the S2 host. Compare the before/after pair only with each other. Use the sweep only to select the config.
