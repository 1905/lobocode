Let the 27B model check several guessed tokens in one pass instead of writing one token per pass. The guesses come from the MTP head already inside our Q6_K file and from text already in the prompt.

Problems

  1. One token per full pass. llama-server starts with no speculation flags, so each output token reads all 22,430,999,840 bytes of weights once. On a 5090 (~1.79 TB/s) that caps output near 80 tok/s, before any overhead (estimate, not measured).
    crates/lobo-agent/src/process.rs:37-70, crates/lobo-proto/catalog.json (qwen38-q6 size)
  2. The MTP head ships but stays unused. Our Q6_K GGUF has the qwen35.nextn_predict_layers key and a blk.N.nextn.* block. llama.cpp loads that block only when MTP is on (mtp_flags = !ml.load_mtp ? TENSOR_SKIP : 0).
    GGUF header of Huihui-Qwen3.8-27B-abliterated-Q6_K.gguf; llama.cpp src/models/qwen35.cpp:36-38, 93-107 at b11118
  3. Coding-agent answers repeat the prompt, and we generate those tokens from scratch. OpenCode edits re-emit large parts of files that are already in the context. Prompt lookup (ngram-mod) can draft those tokens for free. HyperQwen got 260 → 382 tok/s on a 25k-token quoting task on a 3090 this way.
    docs/idea.md:660 (OpenCode is the target client); HyperQwen README
  4. No sustained output speed number exists. The only cloud receipt is 2,186.677 tok/s prompt processing and 45.271 tok/s output over 2 tokens. That cannot judge any speed change.
    docs/implementation-mistakes.md:334-337

Goals

  1. Measure baseline output tok/s, prompt tok/s and repeat-prefix time to first token on the 5090 with the shipped flags. (problem 4)
  2. Raise median chat output tok/s by at least 10% over baseline, with no workload more than 5% slower. (problems 1, 2)
  3. Report the speed-up on quoting workloads (code edit, document Q&A). Target 2× or more; this is a guess, not a ship gate. (problem 3)
  4. Keep output quality: same model file and quant. Greedy outputs match speculation-off on at least 18 of 20 prompts, and every mismatch gets a manual check. (problem 1)
  5. Keep the 65,536-token default context booting on a 5090 with the new flags. (problem 1)
  6. One env switch (LOBO_SPEC) to turn speculation off on a pod without a code change. (problem 1)

Non-goals

  • Switching the engine to vLLM or HyperQwen.
  • 4-bit weights (W4A16, AWQ, AutoRound) or any other quant change.
  • Porting HyperQwen's vLLM patches (15-token fused lookup block) into a llama.cpp fork.
  • A settings control in the Mac app or CLI for speculation.
  • Multi-user batching (--parallel stays 1).
  • Upgrading llama.cpp past b11118 (it already has MTP, DFlash2 and ngram-mod).

What HyperQwen does, and what we take from it

HyperQwen is a vLLM 0.32.0 patch series plus a model preparation pipeline. It was measured on one RTX 3090 at 250 W. Three parts give the speed:

PartTheir resultChanges quality?We take it?
4-bit W4A16 weights, int8 headsFits 27B in 24 GB, faster readsYes: IFBench 78.3 against 79.5 for the full modelNo. We keep Q6_K.
MTP speculation (tuned)82 → 114 tok/sNoYes, llama.cpp draft-mtp
DFlash2 block drafter→ 127 tok/s chatNoP2, gated on P0
Prompt lookup inside the verify block260 → 382 tok/s on 25k quotingNoPartly: llama.cpp ngram-mod, not their fused 15-token block

One 5090 field report (HyperQwen issue #35, 500 W cap, the owner's own client, not their harness) saw 410–449 tok/s on code and 198 tok/s on prose with DFlash2. That is vLLM at 4-bit. Our Q6_K reads ~1.5× more bytes per pass, so expect lower absolute numbers.

Quality

Speculation does not change which tokens the model can output. At every draft position, llama.cpp samples from the 27B model with the normal sampler chain, then compares. It keeps the draft token only when it is equal to that sample, and it stops at the first mismatch:
common/sampling.cpp:678-695 at b11118 
for (; i < draft.size(); i++) {
    const llama_token id = common_sampler_sample(gsmpl, ctx, idxs[i], grammar_first);
    common_sampler_accept(gsmpl, id, true);
    result.push_back(id);
    if (draft[i] != id) {
        break;
    }
}
  • Every output token is a 27B Q6_K sample. A bad draft costs speed, never correctness.
  • One small difference remains. The verify pass runs several tokens in one batch, and batched GPU math can round differently from single-token math. Greedy output can then diverge late in a long answer. That is noise, not a quality loss. Goal 4 measures it.
  • The MTP block comes from huihui-ai's abliterated file. I didn't verify whether abliteration touched it. A mismatch would lower acceptance (speed), not quality.

Benchmark harness (P0)

tools/spec_bench.py runs on the Mac or feesh9. It drives a rented 5090 pod over SSH: it starts /app/llama-server with one flag set, waits for /health, sends the workloads over a forwarded port, records the response timings and stops the server. Then it moves to the next flag set. One weight download serves every config.

  • The pod runs our published latest-qwen38-q6 image, with the entrypoint replaced by sleep infinity, so the agent does not manage llama-server.
  • Weights come from the catalog hf_url() and are checked against the catalog sha256. The DFlash2 Q8_0 file comes from z-lab/Qwen3.8-27B-DFlash2-GGUF.
  • The pod is rented with the runpod skill and terminated at the end, also on failure.

LOBO_SPEC switch (P1)

The pod agent reads LOBO_SPEC the same way it reads LOBO_CTX (crates/lobo-agent/src/config.rs:134). LlamaArgs gets a spec field, and to_args() appends the flags. The default is the P0 winner, as a constant. Nothing in the control plane sets it in P1. It exists for debugging and as an off switch.

LOBO_SPECFlags appended
offnone
mtp--spec-type draft-mtp --spec-draft-n-max <N_MTP>
ngram--spec-type ngram-mod + the P0 ngram values
mtp-ngram (expected default)--spec-type draft-mtp,ngram-mod --spec-draft-n-max <N_MTP> + the P0 ngram values
unset or emptythe default
anything elseagent config error at boot, naming the valid values

The <N_MTP> and ngram values are constants set from results.md. CleanEnv already strips LOBO_* from the llama-server child env (process.rs:12-18), so the switch does not leak.

The status panel's tok/s keeps working. llama-server counts accepted tokens as generated tokens.

DFlash2 drafter (P2, gated)

Built only when P0 shows dflash* is at least 15% faster than the best mtp* config on W1+W2 at default sampling. If the gate passes, this section becomes a plan revision. Shape:

  • Model gets an optional draft reference: file, sha256, size, chunk_sha, repo (crates/lobo-proto/src/catalog.rs:10-23, catalog.json). ts-rs re-exports the type for the app.
  • The download, the chunk verification and docker/pod/build_model.py handle a second file. The thin image fetches both before Ready.
  • LOBO_SPEC gains dflash and dflash-ngram. to_args() adds -md /models/<draft file> and --spec-draft-type-k/-v q8_0.
  • Disk check: min_free_mib counts both files.
Risk. The DFlash2 drafter was trained for base Qwen/Qwen3.8-27B, not huihui-ai's abliterated weights. Acceptance can be lower than the vendor's figures. P0 measures it on our file.

Failure modes & decisions

FailureBehaviour / decision
MTP on this hybrid (recurrent + attention) model is slower than offP0 shows it. The default stays off or ngram, and P1 ships only what wins.
No config reaches +10% on chatDrop P1 and report the table. No code change.
A config wins on quoting but loses >5% on chatNot the default. The gate treats chat as the main workload.
Rejected drafts break recurrent-state rollback and the output is garbledThe greedy match check catches it. That config is disqualified, whatever its speed.
VRAM OOM at 65,536 ctx with the chosen configSeen in P0 first. Pick a smaller n-max or another config. Do not lower the default ctx for speed.
llama-server rejects a flag on a podBoot fails with the llama-server error (last_line, process.rs:72). Fix: new image, or LOBO_SPEC=off for debugging. No automatic fallback in P1 (keeps boot logic simple).
Greedy outputs diverge late in a long answerExpected from batched math. Accept when ≥18/20 match exactly and a manual read finds no quality difference.
W5 repeat TTFT is slow on the hybrid modelTest --checkpoint-min-step values in P0 and pin the winner in P1. If no value helps, report it and leave it.
Bench pod is left runningThe tool terminates the pod in a finally path. The runpod skill pattern ends with terminate.

Out of scope

  • vLLM, HyperQwen images, 4-bit checkpoints (including leminkozey/Qwen3.8-27B-Uncensored-W4A16-AutoRound).

  • App or CLI settings UI for speculation; control-plane plumbing of LOBO_SPEC.
  • GPUs other than the RTX 5090 (the only one offered: provider/runpod.rs:14, provider/vast.rs:258).
